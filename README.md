# Cистема графической аутентификации для РедОС на основе протокола PassPoints
### Краткое описание

PassPoints — прототип системы аутентификации пользователей на основе графического пароля для операционной системы РедОС.

В качестве основного механизма аутентификации используется метод PassPoints, при котором пользователь задаёт секретную последовательность координатных точек на выбранном изображении. Дополнительно применяется символьный пароль, участвующий в формировании проверочного значения.

Программное средство обеспечивает регистрацию пользователей, обработку графических паролей, криптографическое формирование верификаторов и их безопасное хранение.

### Принцип работы

Аутентификация основана на воспроизведении последовательности контрольных точек на ранее выбранном изображении.

Процесс регистрации включает следующие этапы:

1. Ввод идентификатора пользователя и символьного пароля.
2. Выбор фонового изображения.
3. Формирование графического пароля путём последовательного указания контрольных точек.
4. Нормализация координат, обеспечивающая устойчивость к сдвигу и масштабированию.
5. Сериализация нормализованной последовательности точек.
6. Формирование криптографического верификатора.
7. Сохранение идентификатора пользователя и верификатора в файловом хранилище.

При последующей аутентификации пользователь повторно вводит символьный пароль и воспроизводит графический пароль. Система выполняет аналогичную обработку полученных данных, формирует проверочное значение и сравнивает его с сохранённым верификатором.

**Язык разработки**: Python 3.12.3
**Срок разработки**: 3 мес

### Архитектура и стек технологий

Программное средство построено на основе многослойной архитектуры с применением принципов гексагональной архитектуры (Ports and Adapters).

Основные архитектурные уровни:

- **Presentation** — пользовательский интерфейс и взаимодействие с пользователем.
- **Application** — сценарии регистрации и аутентификации, координация компонентов, нормализация и сериализация данных.
- **Domain** — модели предметной области, политики обработки графического пароля и абстракции криптографических операций.
- **Infrastructure** — реализации криптографических алгоритмов и файлового хранилища.

#### Особенности архитектуры

- Разделение ответственности между архитектурными уровнями.
- Использование портов и адаптеров для изоляции прикладной логики от инфраструктурных зависимостей.
- Внедрение зависимостей через DI-контейнер с поддержкой Singleton и Factory.
- Централизованная реализация криптографических операций.
- Нормализация координат графического пароля с центрированием, масштабированием и квантизацией.
- Детерминированная сериализация последовательности точек с фиксированной точностью координат.
- Использование файлового репозитория для хранения аутентификационных данных.

### Безопасность

Защита аутентификационных данных реализована посредством последовательного применения криптографических преобразований:
1. **Streebog-256** — формирование хэш-значения нормализованных данных графического пароля.
2. **Kuznechik CMAC** — формирование имитовставки с использованием мастер-ключа системы.
3. **Salt** — формирование соли на основе идентификатора пользователя и результата MAC.
4. **Argon2id** — получение итогового проверочного значения с использованием вычислительно сложной функции деривации ключа.

Параметры Argon2id в представленной реализации:

- Time Cost: 3.
- Memory Cost: 65536 KiB.
- Parallelism: 2.
- Hash Length: 32 байта.

Дополнительные механизмы защиты:

- Отсутствие хранения исходных графических и символьных паролей.
- Хранение мастер-ключа отдельно от пользовательских аутентификационных данных.
- Ограничение доступа к файловому хранилищу на уровне ОС (права `0600`).
- Атомарная запись данных посредством временного файла и последующей замены основного.
- Проверка корректности формата записей при загрузке.
- Использование `hmac.compare_digest` для сравнения проверочных значений.
- Сокрытие конкретной причины неудачной аутентификации от пользователя.

### Развёртывание

Целевая операционная система — РедОС.

Для работы программного средства необходимы:
- Python с поддержкой используемого синтаксиса проекта.
- Библиотека `gostcrypto`.
- Библиотека `argon2-cffi`.
- PySide6 для графического интерфейса.

Хранилище аутентификационных данных по умолчанию располагается в каталоге:
```
/var/lib/passpoints/shadow_pp
```

Для хранения используется текстовый формат, в котором каждая запись содержит идентификатор пользователя и шестнадцатеричное представление верификатора:

```
user_id:verifier_hex
```

Каталог хранилища создаётся автоматически при инициализации файлового репозитория. Для файла устанавливаются права доступа `0600`.

**Примечание:** проект представляет собой прототип. Перед эксплуатацией необходимо завершить интеграцию пользовательского интерфейса, настроить загрузку мастер-ключа из защищённого источника и обеспечить полноценную конфигурацию параметров приложения.
